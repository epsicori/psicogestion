**Cero avisos `blocking-prerender-*`**. Y `/pacientes` sale como **`◐ Partial Prerender`**,
que es la prueba de que el troceado funciona: si los bloques de datos no estuvieran detrás
de un `<Suspense>`, la ruta entera sería dinámica y el prerenderizado no existiría.

### 2 · Ningún `use cache` sobre datos de paciente, usuario o rol; `use cache: private` en ningún sitio

```
$ grep -rn "use cache" app components lib --include="*.ts" --include="*.tsx"
app/(app)/pacientes/page.tsx:18: * NUNCA `use cache`: eso guarda el resultado entre peticiones y lo compartiría
components/armazon/armazon.tsx:20: * Es `cache()` y NO `use cache` a propósito, y la diferencia importa: `use cache`
```

Las **dos** coincidencias son **comentarios que explican por qué no se usa**. No hay una
sola directiva `use cache` en el repositorio.

Lo que sí se usa es **`cache()` de React**, que es otra cosa y conviene no confundir:
memoiza **dentro de una misma petición**, para que dos bloques que necesitan el mismo dato
—el recuento y la lista de pacientes; la identidad y el saludo— no hagan la consulta dos
veces. No guarda nada entre peticiones, así que no puede servirle a un usuario el perfil ni
los pacientes de otro.

### 3 · Ninguna página envuelve todo su contenido en un solo `<Suspense>`

Dos fronteras por pantalla, cada una alrededor de **un bloque de datos**:

```
app/(app)/pacientes/page.tsx      <Suspense> → <RecuentoDePacientes />
                                  <Suspense> → <ListaDePacientes />
components/armazon/armazon.tsx    <Suspense> → <Identidad />
                                  <Suspense> → <SaludoYFecha />
```

Ni `PaginaPacientes` ni `Armazon` son `async`: el encabezado, el formulario de alta, la
marca y la navegación no dependen de ningún dato y se prerenderizan enteros. El formulario
de alta de paciente **está utilizable antes de que la consulta de la lista termine**, que es
justo lo que se perdería con una sola frontera.

### 6 · Cero colores literales en `app/` y `components/` fuera de `app/globals.css` y `app/prototipo/`

```
$ grep -rnE "#[0-9a-fA-F]{3,8}\b|rgb\(|rgba\(|hsl\(" app components --include="*.ts" --include="*.tsx" --include="*.css" | grep -v "app/prototipo\|app/globals.css"
```

Uno, y es **una excepción obligada, no deuda**: `themeColor` sale como `<meta>` y el
navegador lo lee para pintar **su propia barra ANTES** de aplicar ninguna hoja de estilo.
Una variable CSS ahí todavía no existe. Queda documentado en el propio fichero con el token
del que es copia (`--background`).

móvil usaba `bg-black/30`, un color con nombre en vez de un token. Ahora es
`bg-foreground/30`, que además respeta el tema.

### 7 · Rutas respondiendo de verdad, no solo compilando

```
$ curl -o /dev/null -w "%{http_code} -> %{redirect_url}" http://localhost:3002/
307 -> http://localhost:3002/login
$ curl -o /dev/null -w "%{http_code}" http://localhost:3002/login

$ curl -o /dev/null -w "%{http_code} -> %{redirect_url}" http://localhost:3002/pacientes

```

(Puerto 3002: el 3000 y el 3001 los tenía ocupados otro proceso ajeno al proyecto.)

Sin sesión, el Proxy manda a `/login` antes de que la página llegue a redirigir. Es el
comportamiento correcto y por eso `/` da 307 a `/login` y no a `/agenda`.

### 8 · El contrato de los formularios, con pruebas

`npm test` cubre lo que de verdad cambió —el mecanismo de envío— en
`app/login/formulario-login.test.tsx` (5) y
`app/(app)/pacientes/formulario-nuevo-paciente.test.tsx` (3):

- con el formulario vacío o el correo mal formado, **la Server Action no llega a
  llamarse**: el esquema lo para en cliente;
- con datos válidos se llama **una vez y con el objeto tipado**, no con `FormData`;
- un error **por campo** devuelto por el servidor se pinta **junto a su campo**, con
  `aria-invalid` y `aria-describedby` atados —comprobado en la aserción, no supuesto—;
- al acertar, el formulario de paciente **se vacía**; si la acción falla, **conserva lo
  escrito**.

Las dos primeras se pondrían rojas si se quitara el `zodResolver`, y la tercera si se
volviera a `action={accion}`: no pasan por casualidad.

## Hallazgos

### `/agenda` no existe todavía: entrar por `/` da 404

Consecuencia **conocida y aceptada** del ADR-050, no un descuido. `/agenda` la construyen
T-010 y T-014. Se ha implementado la redirección tal como manda el ADR en vez de apuntar
provisionalmente a `/pacientes`, porque una redirección provisional se queda para siempre.
El recorrido normal no pasa por `/`: el inicio de sesión lleva directo a `/pacientes`.

### La migración a react-hook-form pierde el funcionamiento sin JavaScript

Antes, los dos formularios usaban `action={accion}` y **funcionaban con JavaScript
desactivado**: el navegador enviaba el `FormData` y la Server Action respondía. Con
react-hook-form eso deja de ser posible —la librería ES cliente—, así que ahora sin
JavaScript los formularios no envían.

No es un efecto secundario evitable: es inherente a la tarea que el corte pedía. Se anota
porque **es una capacidad que el proyecto tenía y ha dejado de tener**, y esa decisión
merece ser explícita en vez de descubrirse dentro de seis meses.

### Tres claves de i18n quedan muertas

`modulos.inicio`, `modulos.clinica` y `modulos.usuarios` ya no las usa nadie. `lib/i18n/**`
**no está en el alcance de esta entrega**, así que no se han tocado. El propio catálogo ya
lo anticipa en un comentario. Es limpieza de una línea para quien tenga ese territorio.
