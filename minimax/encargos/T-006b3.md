## 1 · Una página que lee la sesión NO es `async`

El proyecto tiene **Cache Components** activo. Una página cuyo componente por defecto es
`async` y llama a `exigirSesion()` **rompe el build al prerenderizar**. El patrón real, que
está en `app/(app)/pacientes/page.tsx`:

```tsx
import { Suspense } from 'react';
import { Cargando } from '@/components/ui/piezas';

// Lo que depende de la sesión va en un componente async aparte…
async function ContenidoQueDependeDeLaSesion() {
  const sesion = await exigirSesion();
  // …
}

// …y la página NO es async: la cabecera se prerenderiza y llega instantánea.
export default function PaginaX() {
  return (
    <main>
      <header>…</header>
      <Suspense fallback={<Cargando filas={3} />}>
        <ContenidoQueDependeDeLaSesion />
      </Suspense>
    </main>
  );
}
```

`Cargando` viene de `@/components/ui/piezas` y toma `filas`.

## 2 · Un componente de cliente NO consulta la base

La entrega de b1 abría un cliente de navegador dentro de `useState(() => …)` usado como si
fuera `useEffect`. Los datos se leen **en la página, en servidor**, y bajan como propiedad.
Y el cliente de navegador de este proyecto es `crearClienteNavegador()` de
`@/lib/supabase/navegador` — **`@/lib/supabase/client` no existe**.

## 3 · El formulario tiene un patrón, y está escrito

`react-hook-form` + `zodResolver` con **el mismo esquema Zod que valida la acción**, y los
errores del servidor se vuelcan con `aplicarErroresDelServidor`:

```tsx
import { ESTADO_INICIAL, aplicarErroresDelServidor } from '@/lib/formularios';

const { register, handleSubmit, setError, control, formState: { errors } } = useForm<Datos>({
  resolver: zodResolver(esquema),
  defaultValues: { … },
});

const enviar = handleSubmit((datos) => {
  iniciarTransicion(async () => {
    const estado = (await accionDelServidor(datos)) ?? ESTADO_INICIAL;
    aplicarErroresDelServidor(estado, setError);
    setMensaje(estado.mensaje ?? '');
  });
});
```

**La Server Action recibe `datos: unknown` y devuelve `EstadoFormulario`**
(`{ errores?, mensaje? }`), no `FormData` y no un objeto propio. Y reparte los errores con
`z.flattenError(resultado.error).fieldErrors` — **nunca escogiendo campos a mano de una
lista**: en b1 eso dejó fuera el error del `.refine`, que es justo el criterio de
aceptación que había que cumplir.

Para observar un campo, `useWatch({ control, name })`, no `watch()`: el compilador de React
avisa de que `watch()` no se puede memoizar.
