## TOTP: enrolar, retar y verificar

```ts
// 1 · enrolar — devuelve el QR ya listo para pintar
const { data, error } = await supabase.auth.mfa.enroll({
  factorType: 'totp',
  friendlyName: 'Psicogestión',
});
// data: { id, type: 'totp', friendly_name?, totp: { qr_code, secret, uri } }
//
// qr_code es un SVG: para pintarlo, se antepone 'data:image/svg+xml;utf-8,' al valor.
// secret se enseña en un campo tipo contraseña, por si no puede escanear.
// Ninguno de los dos se escribe en consola.

// 2 · retar
const { data: reto } = await supabase.auth.mfa.challenge({ factorId: data.id });
// reto: { id, type: 'totp', expires_at }

// 3 · verificar
const { error } = await supabase.auth.mfa.verify({
  factorId: data.id,
  challengeId: reto.id,
  code: '123456',
});
```

## El nivel de autenticación de la sesión, para la guardia de ruta

```ts
const { data, error } = await supabase.auth.mfa.getAuthenticatorAssuranceLevel();
// data: { currentLevel: 'aal1' | 'aal2' | null, nextLevel: ..., currentAuthenticationMethods }
```

La guardia del grupo `app/(app)/` exige **las dos cosas**: que `estadoDeCuenta()` diga que
no queda paso pendiente, y que `currentLevel` sea `'aal2'`. Solo con el estado de la base no
basta —la base no sabe si esta sesión pasó el segundo factor—, y solo con el nivel tampoco
—el nivel no sabe si falta el PIN—.
