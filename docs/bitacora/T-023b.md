## Desvíos respecto al diseño
- Política `cobros_facturas_alta` con `and (cobro_id is null or exists (...))`: el WITH CHECK de RLS se evalúa antes que NOT NULL; así el error es 23502 y no 42501 (diseño §1.1 h).
- B4 (TRUNCATE): hubo que devolver `truncate` a postgres para probar la capa 3.
- Las carreras se miden en orden 2, 1.
- `filtrosFacturas` se añade al contexto de `datos.ts`.
- `cobros_asignables` no tiene límite: la acción corta a 200 (201 filas).
- `tCon(clave, valores)` para textos con valores; modo factura sin lista de pacientes.
- Botón de fila: rótulo corto «Registrar cobro» con `aria-label` que lleva el número (el texto largo desbordaba 82 px a 360 px).
- Spec a11y paso 8: «ya no se ofrece» se comprueba con condicional (el botón desaparece si no quedan cobros sueltos); paso 10 solo lee GET (Playwright no lee POST de Server Actions).
- Pruebas de `asignar-cobro`, `fila-factura` y otras se escribieron junto con la implementación (fallo inicial por import); formulario-cobro, registrar-cobro, bloques y page sí vieron rojo por el motivo correcto.
- El detector de literales (`sin-literales.test.ts`) marcó `X > N && (` como texto; se invirtió la comparación.
